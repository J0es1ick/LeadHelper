# Сообщения, аватарки и отправка файлов Битрикса

В версии 0.2.14 сообщения, новости, вложенные карточки и превью используют общий разбор форматирования. Упоминания вида `[USER=726 REPLACE]Имя[/USER]` показываются как имя; ссылки, выделения и цитаты получают оформление. Служебные записи о входе в чат показаны компактно. Обычные квадратные скобки и содержимое блоков кода сохраняются. В уведомлениях, включая оповещения рабочего стола, разметка преобразуется в текст; новые уведомления очищаются до сокращения длины.

Аватарки берутся из уже загруженных ответов чатов и пользователей. Они показываются в списке чатов, заголовке диалога, у авторов сообщений и новостей, у сотрудников и руководителей отделов. Если фотографии нет или её не удалось загрузить, остаются инициалы. Фотографии загружаются по мере появления на экране, без дополнительных запросов к REST для каждого автора. Используются HTTPS-ссылки портала и CDN Битрикса; вебхук в браузер не передаётся.

## Как отправить вложение

- Нажмите скрепку рядом с полем сообщения, перетащите файлы в открытый диалог или вставьте изображение из буфера обмена.
- Проверьте список: изображения имеют миниатюры, у всех файлов видны имя и размер. Ненужный файл можно убрать крестиком.
- При необходимости напишите подпись и нажмите «Отправить». Без нажатия файлы остаются на компьютере. Можно отправить файл без текста.
- Во время загрузки показывается прогресс. Файлы отправляются последовательно, каждый отдельным сообщением; подпись сопровождает первый файл.

До 10 файлов за раз, до 25 МБ на файл и до 100 МБ суммарно. Пустые файлы отклоняются. Выбранные файлы сохраняются при переключении между чатами и вкладками Битрикса в рамках открытого раздела; перезагрузка страницы или выход из раздела очищает несохранённые черновики. При переключении чата начатая отправка продолжает использовать исходного получателя.

Подтверждённые отправки убираются из черновика. При сбое остальные файлы остаются; если результат отправки неизвестен, повтор блокируется до проверки чата пользователем. Автоматической повторной отправки нет. Повтор одного requestId с тем же содержимым возвращает сохранённый результат без нового сообщения в течение 30 минут работы процесса. При перезапуске сервера эти записи теряются, поэтому после потери связи нужно проверить историю.

Для загрузки используется `im.v2.File.upload` с правом `im`, от имени пользователя подключения. Метод одновременно загружает файл, прикрепляет его и отправляет сообщение. Доступ зависит от версии Битрикса и прав пользователя на чат. В интерфейсе нет автоматически отправляемых тестовых сообщений.

## API и проверка

`POST /api/bitrix/chats/{id}/files`, multipart/form-data: один `file`, необязательный `text`, обязательные `accountId` и `requestId`. Нужен `X-LeadHelper: 1`. Ответ: `{messageId,fileId}`. Валидация — 400; неподтверждённая отправка — 502 с `{error,uncertain:true}`. Сервис проверяет рабочий режим, модуль, аккаунт, размер, идентификатор диалога и повторную отправку. Одновременно допускается до двух загрузок. Клиент не получает секрет подключения.

Автотесты проверяют упоминания с REPLACE, безопасное форматирование, получение аватарок без дополнительных запросов, замену недоступного фото и отправку multipart. Отдельно проверяются повторный requestId, потеря подтверждения, неверный аккаунт, переключение чатов, перетаскивание, буфер обмена и частичная отправка очереди. Проверки отправки используют тестовые адаптеры и ответы; реальным людям файлы не отправляются.

Документация Битрикса: [форматирование сообщений](https://apidocs.bitrix24.ru/api-reference/chats/messages/formatting.html), [список чатов и аватары](https://apidocs.bitrix24.ru/api-reference/chats/im-recent-list.html), [отправка файла](https://apidocs.bitrix24.ru/api-reference/chat-bots/chat-bots-v2/im.v2/files/file-upload.html).
