# Проекты и Google Таблицы

Версия 0.2.11 читает матрицы со статусами в датированных столбцах, вертикальную историю «Дата / Статус» и лист с историей одного проекта. Скрытые строки и листы сохраняются с признаком видимости и исключаются из обычного списка и счётчиков. Их можно увидеть через «Показать скрытые в таблице». Разделы распознаются по отдельной жирной строке, проект без статуса сохраняется. Год в датах восстанавливается только при наличии явного года в заголовках.

Снимок в `data/projects-sheet-bootstrap.json` содержит данные пользователя и исключён из Git. В версии 0.2.11 исправлена ошибка старого импорта, который считал скрытые строки и листы обычными проектами. При первом запуске обновления применяется проверенная видимость строк; содержимое проектов, история и ручные правки сохраняются. Повторный запуск не откатывает результаты последующей синхронизации.

В интерфейсе: папки исходной книги, поиск, SQL-пагинация по 25 проектов в боковом списке, полный статус и история в панели справа. Дополнительные исходные поля можно менять в редакторе. История не отправляется вместе с каждой страницей карточек.

## Однократное подключение

Доступ приложения к Google настраивается отдельно от подключения Google Drive в ChatGPT. В разделе «Проекты» нажмите «Подключить синхронизацию». Там доступны скрипт и эти шаги:

1. В исходной Google Таблице откройте **Расширения → Apps Script**.
2. Скопируйте содержимое `frontend/public/project-sheets.gs` в редактор и сохраните.
3. Добавьте **Сервисы → Google Sheets API**.
4. Запустите `setupLeadHelper`, разрешите доступ. Вернитесь на вкладку таблицы: окно покажет секрет подключения.
5. **Начать развёртывание → Новое развёртывание → Веб-приложение**: запуск от своего имени, доступ «Все». Политика Google Workspace должна разрешать такое развёртывание. Если такого варианта нет, потребуется разрешение администратора или отдельная OAuth-интеграция.
6. Вставьте URL `/exec` и секрет в форму LeadHelper. Нажмите «Проверить и подключить».

Исходная таблица не требует публичного доступа. Веб-приложение проверяет случайный секрет для каждого запроса. LeadHelper хранит секрет на сервере в существующем защищённом хранилище интеграций; браузер не получает сохранённый секрет. При обновлении скрипта опубликуйте новую версию существующего развёртывания, сохранив его URL.

## Обмен данными

- Сервер проверяет книгу каждую минуту; браузер может быть закрыт. Требуется запущенный LeadHelper и сеть.
- Названия проектов, ответственные при наличии исходного столбца, дополнительные поля и новые статусы записываются в исходные строки. Для статуса используется датированный столбец LeadHelper; для вертикальной истории добавляется строка. Повторные изменения в тот же день обновляют дневной статус.
- Поля без соответствующего исходного столбца сохраняются в скрытом служебном листе `__LeadHelper`. Не удаляйте его: он также хранит подтверждения операций.
- Новые проекты с включённым флажком отправки добавляются в лист `Проекты LeadHelper` в той же книге. Без флажка проект остаётся локальным.
- Идентификаторы строк хранятся в developer metadata и следуют за перемещением строк. Формулы не перезаписываются: поле с формулой нужно менять в Google Таблице.
- Локальные правки сохраняются до отправки. Изменения разных полей объединяются; изменения одного поля с обеих сторон требуют решения в карточке проекта. Удалённая исходная строка не удаляет локальную копию.
- Запись проекта и подтверждение операции выполняются одним Google Sheets `batchUpdate`. Повтор запроса после потери ответа не дублирует запись.

Ограничения: книга до 40 листов, 300000 ячеек, 5000 строк и 400 столбцов на лист; за цикл отправляется до 10 изменённых проектов. Изменения строк/столбцов человеком между проверкой версии и записью Google API не защищает транзакцией сравнения версии; при массовой перестройке таблицы временно остановите сервис. Скрипт проверяет исходную ревизию непосредственно перед записью и сериализует свои запросы.

Без развёрнутого скрипта доступен импортированный снимок и локальное редактирование; автоматический обмен ещё не работает. Проверки адаптера и скрипта выполняются с тестовыми данными; живой обмен проверяется при подключении пользователем.

## Видимость строк и листов

Скрипт версии 0.2.11 получает `hiddenByUser` и `hiddenByFilter` одним ограниченным запросом метаданных на книгу. Скрытие не означает завершение проекта: исходное состояние сохраняется. Возвращение строки или листа в видимое состояние возвращает проект в обычный список при следующей синхронизации. Исторические записи внутри проекта сохраняются полностью. Персональные представления фильтра браузера не задают общий список проектов.

Если подключение было настроено со старым скриптом, замените код Apps Script и опубликуйте новую версию развёртывания с тем же URL. Снимки старого скрипта не снимают уже подтверждённые признаки скрытых строк, но новые изменения видимости требуют обновлённого скрипта.
