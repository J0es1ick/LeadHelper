# HTTP API v0.2.14

В 0.2.14 добавлена [отправка файлов в чаты Битрикса](bitrix-content.md): `POST /bitrix/chats/{id}/files`, multipart/form-data с `file`, `text`, `accountId` и `requestId`. Ответ — `{messageId,fileId}`. Повтор запроса с тем же ID и содержимым не создаёт новое сообщение. `RemoteItem` дополнен `avatarUrl`, `headAvatarUrl` и `system`.

В 0.2.13 добавлена [выгрузка фактических часов команды в Excel](worklog-export.md):

| Метод | Маршрут | Действие |
| --- | --- | --- |
| POST | `/jira/worklog-exports` | Запустить выгрузку: `{from,to,split,boundary,weekdays,dates,memberIds}`. `split`: none/weekly/dates; `boundary`: start/end; weekdays: ISO 1–7; даты YYYY-MM-DD |
| GET | `/jira/worklog-exports/{id}` | Состояние `{id,state,done,chunks,employees,missing,error?}`; state: running/ready/error/cancelled; done/chunks — прогресс частей загрузки |
| DELETE | `/jira/worklog-exports/{id}` | Отменить выполняющуюся выгрузку |
| GET | `/jira/worklog-exports/{id}/file` | Скачать XLSX после ready; 409, если ещё не готов; 404 для отсутствующей или истёкшей выгрузки |

POST возвращает статус с ID сразу, дальнейшая загрузка идёт в фоне. Период 1–366 дней, 1–500 выбранных действующих сотрудников, необходимы рабочий режим и подключённая Jira. Одновременно выполняется одна выгрузка; результаты хранятся в памяти до 30 минут, не переживают перезапуск. Сбой части не создаёт файл с неполными данными.

В 0.2.8 добавлены [проекты и импорт таблиц](projects.md). Все маршруты ниже относительно `/api`, сохраняют ограничения модуля и разделение демонстрационных/рабочих данных:

| Метод | Маршрут | Действие |
| --- | --- | --- |
| GET | `/projects?state=active&page=1&limit=25&search=` | `{items,total,page,limit,counts}`; state: active/completed/archived/all, limit 1–100 |
| POST | `/projects` | Создание/обновление полной карточки: `{id,name,status,state,owner,description,startDate,dueDate,url,source,version}`; при создании id пустой, version 0 |
| POST | `/projects/import/parse` | `{name,data}`: имя файла и base64 XLSX/CSV/TSV, до 5 МиБ; возвращает `sheets` и `styles` общего просмотрщика |
| POST | `/projects/import/preview` | `{projects,merge,fields}`: список строк, флаг обновления по имени, массив выбранных полей; возвращает карточки с ID/версиями, ничего не записывает |
| POST | `/projects/import` | `{projects,requestId}` из предпросмотра; атомарное сохранение до 200 проектов, повтор того же requestId с тем же пакетом безопасен |

При обновлении нужна актуальная `version`; конфликт или изменение режима возвращает ошибку, не перезаписывая данные. `status` — свободная строка; `state` — active/completed/archived. `fields` содержит name/status/owner/description/startDate/dueDate/url; невыбранные поля существующего проекта сохраняются. Пакеты с усечённой таблицей отвергаются.

Просмотр Office: метаданные DOCX возвращают `kind:docx` и резервный `text`. Защищённый маршрут `/preview/content?format=docx` отдаёт проверенный DOCX в локальный sandbox просмотрщик; для Битрикса требуется также `account`. В XLSX добавлены `styles`, а в листах — `cells`, `widths`, `heights`, `merges`, `date1904`. [Ограничения и библиотеки](office-preview.md).

В 0.2.7 добавлен `PATCH /bitrix/chats/{id}/read` с телом `{accountId,messageId}`. Метод подтверждает прочтение через Битрикс только до указанного сообщения и возвращает `{messageId,unread}`. `accountId` берётся из ответа `/workspace/bitrix` для чатов/сообщений; `readMessageId` в карточке чата — последний прочитанный ID из Битрикса. После подтверждения соответствующие уведомления получают `read:true`; более новые, другие диалоги и подключения не затрагиваются. Загрузка сообщений методом GET сама по себе ничего не отмечает прочитанным.

Прочтение письма или переписки также закрывает связанные уведомления. Прочитанные оповещения не показываются в окне уведомлений, но остаются в ограниченной истории для защиты от повторов. [Подробности и проверки](notification-reads.md).

В 0.2.6 недельные ячейки `/jira/worklogs` дополнены `taskCount` и `tasks`: ключ и название задачи, сумма секунд и число её списаний за день. Повторные списания объединены по сотруднику, дате и задаче. Возвращаются до 10 задач на ячейку, отсортированных по времени (затем по ключу); `seconds`, `count`, `taskCount` учитывают весь день. Полные записи доступны постранично через `/jira/worklogs/day`.

Предпросмотр Битрикса: `GET /bitrix/files/{id}/preview?account=ID` возвращает тот же DTO, что и предпросмотр почты. `GET /bitrix/files/{id}/preview/content?account=ID` отдаёт проверенные изображения/PDF с поддержкой Range. Оригинал скачивается по `/bitrix/files/{id}?account=ID`. Файловые карточки в `/workspace/bitrix?kind=files` теперь также содержат `attachments` с локальными URL. Данные файла кратковременно кешируются на сервере (1 минута, максимум 64 МиБ / 64 файла), проверка модуля, режима и подключения повторяется для каждого запроса; одновременно загружается не более 2 файлов.

Создание Jira, списания и файлы чатов описаны подробнее в [jira-creation-worklogs.md](jira-creation-worklogs.md).

Для создания задач `requestId` должен быть уникальным ID длиной 16–100 символов. Повтор с тем же содержимым возвращает результат; 409 при неизвестном исходе запрещает повторную внешнюю запись. После подтверждённой ошибки 400 разрешено исправить поля и повторить. Новая задача может не входить в JQL текущего бэклога.

`taskMetrics.worklogAvailable`, `worklogHours`, `worklogSyncedAt` дают фактические часы текущей недели без сетевого запроса к Jira. Прежний `memberHours` остаётся суммой ручного плана.

Base URL: `http://localhost:8090/api`. JSON в UTF-8. Для всех операций записи нужен заголовок `X-LeadHelper: 1`. Это защита локального экземпляра от cross-site form requests, не аутентификация. Host ограничен localhost / loopback. Ошибки: `{ "error": "описание" }`; 400 — валидация, 403 — модуль выключен / граница запроса, 404 — отсутствующая запись, 500 — внутренняя ошибка.

Типы DTO описаны в `frontend/src/shared/types.ts` и `backend/internal/domain/model.go`. `PUT` требует актуальную полную сущность; сервер сам назначает ID, время, источник и признак демонстрации. Неизвестные JSON-поля отвергаются. Размер JSON-запроса ограничен 8 МБ.

`GET /state` содержит `revision`, точные агрегаты `taskMetrics` и ограниченный набор превью: до 5 открытых командных задач и 25 личных задач на сегодня. Полный архив и массив распределения задач туда не включаются. Клиент не должен рассчитывать общие показатели по `state.tasks`.

`GET /tasks` возвращает `{items,total,page,limit,pages}`. `limit` — до 50. Номер за пределами списка приводится к последней странице. Фильтры: `personal=false|true|all`, `status=all|active|actionable|backlog|todo|progress|review|done`, `assignee=all|ID` (пустой — без исполнителя), `source`, `priority`, `search`, `sort=due`, `from`/`to` для даты личного плана (`from=none` — без даты). Поиск включает название, описание, ключ и проект; описание в списке не возвращается. Порядок стабилизирован ID задачи. Для редактирования сначала загрузить полную карточку через `/tasks/{id}`.

План дня сохраняется телом `{ "revision": "ревизия из GET", "entries": [{ "taskId": "ID", "hours": 2.5 }] }`. Пустой `entries` очищает день. Часы необязательны: 0 означает «не указаны», допустимый диапазон 0–24 на задачу; до 200 выбранных задач на день. Одна задача может повторяться в разных днях. Новые задачи должны принадлежать выбранному сотруднику и быть в `todo` или `progress`; уже выбранные завершённые задачи сохраняются как история. Поля Jira не меняются. Ошибка **409** означает, что сохранённый план изменился после открытия: перечитать его перед повторной записью. При ошибке транзакция целиком откатывается.

Недельная ячейка содержит точное число задач, сумму часов, число задач без часов и до 3 превью. Старые одиночные даты командного плана переносятся один раз при запуске; личный план продолжает использовать `plannedDate`.

Предпросмотр сохраняет ограничения модуля и деморежима. HTML/SVG показываются только текстом, неподдерживаемые форматы скачиваются. PDF рендерится локальным PDF.js 5.6.205 с отключёнными JavaScript-вычислениями документа и XFA; просмотрщик загружается по требованию. DOCX рендерится с оформлением и имеет текстовый резервный режим; PPTX извлекается в текст. XLSX показывает сохранённые значения с форматированием, без пересчёта формул. Лимиты: текст 1 МиБ, Office XML 8 МиБ на часть / 32 МиБ суммарно, XLSX до 10 листов по 200 строк и 50 столбцов; усечение явно отмечается в ответе. Большие/повреждённые/зашифрованные документы доступны для скачивания оригиналом.

Минимальное создание задачи:

```json
{
  "title": "Подготовить план спринта",
  "description": "Согласовать объём с командой",
  "status": "todo",
  "priority": "high",
  "project": "Платформа",
  "assigneeId": "",
  "estimate": 2,
  "dueDate": "2026-11-12",
  "plannedDate": "2026-11-10",
  "personal": false,
  "tags": ["планирование"]
}
```

Статусы: `backlog`, `todo`, `progress`, `review`, `done`. Приоритеты: `low`, `medium`, `high`, `critical`. Источники задаются сервером: `local`, `jira`, `bitrix`.

Синхронизация возвращает HTTP 200 с `success: false`, если провайдер вернул штатную ошибку: такая попытка сохранена в журнале. Ошибка самого хранилища или запрет модуля возвращается соответствующим HTTP-кодом. Клиент обязан проверять поле `success`.

## Порционная загрузка почты

- `GET /api/mail-threads?folder=inbox&limit=25&search=...&cursor=...` — `items`, `nextCursor`, `limit`. Размер 1–100; интерфейс предлагает 25/50/100. Папки: inbox, sent, drafts, archive, trash, starred, all. Курсор привязан к режиму, папке и запросу. Тела сокращены до 220 символов; HTML и base64 отсутствуют.
- `GET /api/mail-threads/{id}?folder=inbox&limit=20&cursor=...` — `items`, `thread`, `nextCursor`; заголовки от новых к старым. Серверные копии с одинаковым Message-ID показаны один раз.
- `GET /api/mail/{id}` — одно полное письмо. Доступ проверяется по деморежиму и включённому модулю; вложения доступны отдельными запросами.
- `PATCH /api/mail-threads/{id}?folder=inbox` — атомарное локальное изменение всей переписки: `folder`, `read`, `starred`. Для корзины укажите `folder=trash` в запросе.
- `GET /api/state` возвращает максимум три почтовых анонса, `mailStats` (счётчики папок, непрочитанное, revision) и `mailConnection` (email, host, configured). Это больше не API выгрузки всего ящика.

Новые поля письма: html, messageId, inReplyTo, references. Поля вложения: contentId и inline. HTML очищается; локальные CID разрешаются через защищённые маршруты вложений, внешние картинки загружаются только после нажатия в письме.
