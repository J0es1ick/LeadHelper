# Прочтение и уведомления — 0.2.7

Окно уведомлений показывает только актуальные непрочитанные оповещения. При чтении письма или переписки связанные оповещения закрываются; счётчик колокольчика обновляется сразу после сохранения. Старые уведомления о уже прочитанных письмах также исключаются. «Прочитать все» закрывает оповещения, не помечая сами письма и чаты прочитанными. Переход из уведомления не закрывает его до успешного просмотра содержимого. История остаётся ограниченной 200 записями для дедупликации.

В Битриксе просмотр видимых сообщений активной вкладки отправляет `im.dialog.read` с конкретным `MESSAGE_ID`. Ответ Битрикса подтверждает отметку и оставшийся счётчик. Нельзя использовать вызов без ID: он мог бы отметить сообщения, пришедшие после загрузки диалога. Фоновая вкладка, закрывающая чат модальная панель, непоказанные сообщения ниже прокрутки и ошибка загрузки не считаются просмотром. При ошибке подтверждения счётчик сохраняется, интерфейс предлагает повтор. Чтение старой страницы не закрывает уведомления о более новых сообщениях.

Список чатов обновляется каждые 15 секунд. Поле `last_id` и нулевой счётчик из Битрикса позволяют закрыть уведомления о сообщениях, прочитанных в другом клиенте. Фоновая проверка новых чатов также сверяет полученные отметки. Изменения в другом клиенте отражаются при очередной проверке; это опрос, а не мгновенные push-события. Подписки на системные уведомления остаются отдельной настройкой; созданное этой вкладкой системное окно закрывается, когда все его сообщения прочитаны.

Сообщения без текста показываются в списке чатов как «📎 Вложение», «Стикер» или «Прикреплённые материалы» по метаданным Битрикса. «Нет сообщений» остаётся только для пустого диалога.

Статус писем и связанных уведомлений фиксируется в одной транзакции SQLite. Проверяются только ID целей ограниченного списка оповещений по индексу сообщений; весь почтовый архив не загружается. Чтение чатов сериализовано с фоновой синхронизацией уведомлений, чтобы старый ответ опроса не восстановил закрытое оповещение. Подключение проверяется по accountId.

Проверки: Go-тесты точного ID прочтения, отказов API, разных диалогов и аккаунтов, внешнего прочтения, старых почтовых уведомлений, транзакционного статуса переписки и новых писем после её просмотра. Проверка через браузер на локальном стенде охватывает счётчики, перезагрузку, фоновую вкладку, вложение без текста, ошибки загрузки/отметки, переход из уведомления, новое сообщение при просмотре истории, обе темы. Реальные чаты и письма для тестов не изменяются.

API Битрикса: [im.dialog.read](https://apidocs.bitrix24.com/api-reference/chats/messages/im-dialog-read.html), [im.recent.list](https://apidocs.bitrix24.com/api-reference/chats/im-recent-list.html).
