# Подключения LeadHelper · версия 0.2

Подготовленное обновление: `& C:\git\LeadHelper\scripts\update.ps1`, затем обновить страницу. Запускать из своей учётной записи Windows: сохранённый почтовый пароль защищён DPAPI.

## Почта Timeweb

Существующее подключение `imap.timeweb.ru:993` используется для чтения и сохранения копии отправленного письма. SMTP — `smtp.timeweb.ru:465`, проверяемый TLS, тот же логин и пароль. При настроенном Timeweb параметры SMTP определяются автоматически. `ALLOW_LIVE_MAIL_SEND=true` разрешает отправку только по нажатию пользователем кнопки «Отправить».

Поддерживаются To/CC, текст и HTML, обычные вложения и CID-изображения. После положительного ответа SMTP письмо отмечается отправленным локально, затем копируется через IMAP APPEND в серверную папку Sent. Неудачная запись копии не отменяет доставку и показывается предупреждением. При явном отказе SMTP черновик можно исправить и повторить отправку. Неизвестный результат передачи блокирует повтор: сначала проверить почту. Автоматических повторных отправок нет.

Другой SMTP: `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY=tls|starttls`, при необходимости `SMTP_USER`, `SMTP_PASSWORD_FILE`. Пароль из IMAP используется, если отдельный пароль не указан. Незашифрованная авторизация не поддерживается.

Письма загружаются фоновым worker, включая дозагрузку после простоя. Список переписок и сообщения внутри них имеют серверную пагинацию. Отметки прочтения, звёздочки и перемещения пока локальные; удаления и изменения флагов на сервере не зеркалируются.

## Jira

В LeadHelper открыть «Интеграции» → Jira → «Подключить».

- Адрес вашего сервера Jira, тип Server / Data Center. Для Jira Cloud выберите Cloud и укажите email и API token.
- В своём профиле Jira создать Personal access token и ввести в поле токена.
- Режим по умолчанию — «Команда из Битрикса». Пустой дополнительный JQL означает все задачи только действующих сотрудников этой команды, из любых доступных проектов. Запрос в Jira обязательно содержит `assignee IN (...)`; ограничение применяется до пагинации.
- В разделе «Команда и исполнители Jira» отображается сопоставление аккаунтов. Точное уникальное совпадение рабочего email связывается автоматически; совпадение имени не используется. Для скрытых или разных адресов предусмотрен поиск по имени, логину или email и явный выбор аккаунта. Поиск требует разрешения Jira на просмотр пользователей.
- Пока есть несопоставленные сотрудники, загрузка задач не выполняется; прежние задачи сохраняются. Нет команды, ошибка источника, смена состава во время запроса или повторная страница также не приводят к расширению выборки на всю Jira.
- Дополнительный JQL объединяется с фильтром команды через `AND`, включая запросы с `OR` и `ORDER BY`. Режим «Собственная выборка по JQL» явно отключает фильтр команды и требует непустого JQL.

Server использует REST v2 и Bearer PAT; Cloud — REST v3, email и API token. Постраничная загрузка, обновление исполнителей, сохранение локального плана. Проверка каждую минуту и по кнопке. Задачи, исчезнувшие из доступной выборки, убираются из локального представления. Максимум 10 000 задач за синхронизацию; при превышении показывается ошибка без частичного обновления. Запись задач обратно в Jira не включена: редактирование источника — в Jira, личное планирование — в LeadHelper.

В режиме команды Jira-задачи назначаются существующим участникам из Битрикса, их доступные часы и личные даты планирования сохраняются. Старые отдельные карточки исполнителей Jira переводятся в неактивные, связанные задачи переназначаются на совпавшую карточку Битрикса. Внешние задачи и аккаунты не изменяются. Идентификаторы привязаны к серверу Jira; при его смене требуется повторное сопоставление.

## Битрикс24

На `https://garpix.bitrix24.ru` создать входящий вебхук от своего пользователя. Нужны области `im`, `log`, `user`, `department`, `calendar`, `disk`. Вставить полный URL вебхука в защищённое поле в LeadHelper → «Интеграции» → Битрикс24. URL не отправлять в чат и не включать в скриншоты.

Реализованы:

- Чаты: постоянная боковая колонка и диалог справа, страницы по 50 сообщений, свои ответы справа, даты, отправка текстового ответа по кнопке. На узком экране есть возврат к списку.
- Новости идут одной вертикальной лентой, новые сверху; по 30 записей. Курсор берётся из `next` ответа API (верхний уровень или внутри `result`), это ID записи ленты, а не ID публикации. Неполная страница с курсором не считается концом ленты.
- Сотрудники: общее число аккаунтов типа `employee`, число найденных, фильтры «Все», «В компании», «Уволенные», «Онлайн», поиск имени и фамилии, фильтр отдела. Списки по 50 аккаунтов, итоги берутся из `total` Битрикса.
- Отделы: полное дерево `PARENT`, имена руководителей по `UF_HEAD`, поиск, раскрытие веток и переход к сотрудникам отдела. Отдел без доступного родителя остаётся видимым.
- Каталоги диска и ссылки на исходные записи.
- Фоновая проверка новых входящих сообщений Битрикса каждые 10 секунд.
- Занятость пользователя в «Моём плане»: выбранная неделя и день, время МСК, название события, место и ссылка. Данные `calendar.accessibility.get` дополняются описанием из `calendar.event.get`; повторы берутся у сервера, отклонённые/удалённые события исключаются, пересечения не удваивают занятые часы. События со статусом «свободен» не блокируют время.

Задачи Битрикса не импортируются. Правила портала и тариф могут ограничивать REST, вебхуки или отдельные методы; ошибки показаны в соответствующем разделе. Если портал запрещает необходимые методы входящему вебхуку, потребуется разрешение администратора либо отдельный OAuth-адаптер — OAuth в этой версии не реализован.

## Команда из структуры Битрикса

В «Загрузке команды» кнопка «Подключить мою команду» находит отделы, где пользователь вебхука указан руководителем (`UF_HEAD`), и обходит все вложенные подразделения по `PARENT`. Членство пользователя в отделе само по себе не даёт оснований включать весь отдел. Пересекающиеся ветки и сотрудники нескольких подразделений не дублируются; сам руководитель исключается. Загружаются только действующие сотрудники типа `employee`.

После включения состав обновляется фоновым worker каждую минуту при запущенном сервисе и включённых модулях команды и Битрикса. Есть ручное обновление и пауза. Новым участникам задаётся стартовая доступность 32 ч/нед.; это явно показанный настраиваемый параметр планирования, а не часы из Битрикса. Изменённые часы сохраняются при повторных обновлениях.

Сотрудники, покинувшие структуру, становятся неактивными: прежние задачи, идентификаторы и доступность сохраняются, новые задачи им назначить нельзя. При возвращении восстанавливается прежняя запись. Если загрузка неполная, произошла ошибка, подключение изменилось во время загрузки или не удалось подтвердить отдел руководителя, предыдущий состав не очищается. Деморежим не обращается к рабочему Битриксу.

## Confluence

Адрес вашего сервера Confluence. Создать отдельный Personal access token в профиле Confluence и ввести в форме подключения. Доступны общие и личные пространства согласно правам пользователя, страницы, поиск по содержимому и чтение страницы. Пагинация по 25 записей. Встроенные скрипты и внешние изображения не исполняются/не загружаются; оригинал можно открыть в Confluence. Изменение страниц выполняется в исходном сервисе.

PAT поддерживаются в Jira начиная с 8.14, в Confluence с 7.9. Если пункта создания токена нет, нужна проверка версии и политики администратора. Cloud API token не заменяет PAT серверной установки.

## Уведомления

Колокольчик показывает до 200 последних уведомлений о новых непрочитанных письмах и входящих сообщениях Битрикса. Прочтение сохраняется на сервере. Первая загрузка истории и смена UIDVALIDITY не вызывают массовых уведомлений; повторная синхронизация не создаёт дубли. Для чата показывается последнее новое сообщение на момент проверки, а не отдельное оповещение на каждый промежуточный ответ.

В настройках или окне уведомлений можно включить системные оповещения и разрешить их в браузере. Они работают при запущенном LeadHelper и открытой вкладке, в том числе в фоне. При закрытом браузере работает только серверная загрузка и сохранение уведомлений; это не автономный Windows push-сервис.

## Хранение и запуск

Токены сохраняются в `data/integration-secrets.bin`, зашифрованном DPAPI текущего пользователя Windows. API возвращает только публичные параметры; вебхук и токены не возвращаются в браузер. Перенос одного файла на другую машину/учётную запись не переносит доступ. Пароль почты остаётся в существующем `imap-credential.xml`. Для Linux/Docker — секреты окружения сервера; форма записи Windows-хранилища там недоступна.

Конфигурация Jira/Битрикса/Confluence из формы применяется без перезапуска. Смена SMTP/IMAP через окружение требует перезапуска. Данные приложения хранятся в SQLite, оригиналы и вложения — в отдельных файлах. Секреты не попадают в SQLite, логи или отчёты.

Почта и Битрикс подключены. Чтение чатов, пагинация новостей и сотрудников, фильтры, структура отделов и имена руководителей проверены на подключённом портале. Jira и Confluence требуют отдельных PAT. Отправку проверяли синтетическими SMTP/IMAP/HTTP-фикстурами; реальные письма и сообщения без указанного пользователем получателя и содержания не отправлялись.

После открытия переписки отметка прочтения применяется ко всей цепочке, включая старые ответы и копии; список и счётчики обновляются после сохранения. HTML приложения отдаётся без кеширования; открытая вкладка проверяет версию интерфейса и предлагает обновить страницу, сохранив перед этим черновики. Принудительной перезагрузки нет.
