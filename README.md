# LeadHelper

## Запуск

### Docker Compose

Требуется запущенный Docker Desktop с Linux containers и Docker Compose v2.

```powershell
Copy-Item .env.example .env
docker compose up -d --build
docker compose ps
```

После первого запуска откройте http://localhost:8090. Секреты для демонстрации не нужны. Контейнер получает статус `healthy`, данные сохраняются в именованном volume `leadhelper_leadhelper-data`. Порт привязан только к loopback компьютера.

```powershell
docker compose logs --tail 50 app
docker compose down
```

`down` сохраняет данные. Не используйте `down -v`, если хотите сохранить пространство. Docker и локальный запуск используют разные хранилища. Одновременно на порту 8090 запускается только один экземпляр; для Docker можно изменить `LEADHELPER_PORT` в `.env`.

### Локально на Windows

```powershell
.\scripts\start.ps1
```

Скрипт запускает сервер в фоне без отдельного окна. При необходимости соберёт проект (Node.js 22 и Go 1.25+). Остановка и пересборка:

```powershell
.\scripts\stop.ps1
.\scripts\start.ps1 -Rebuild
```

Локальные данные: `data/leadhelper.json.sqlite` и `data/mail-blobs/`. При первом запуске новой версии существующий `data/leadhelper.json` автоматически переносится в SQLite; исходный JSON остаётся без изменений как резервная копия. Последующие записи идут только в SQLite. Для резервной копии остановите сервер и скопируйте SQLite вместе с оставшимися файлами `-wal`/`-shm` (если есть) и каталогом вложений. Не заменяйте старый JSON для восстановления новой версии. Логи: `data/server.err.log`. Один рабочий сервер на каталог данных.

### Разработка

```powershell
# Терминал 1
cd backend
go run -buildvcs=false ./cmd/server

# Терминал 2
cd frontend
npm ci
npm run dev
```

Vite: http://localhost:5173. Запросы `/api` проксируются в Go на 8090. Без Vite сервер Go раздаёт готовую сборку из `frontend/dist`.

## Демонстрация и рабочие данные

При первом запуске добавляются 5 участников, 12 командных задач, 4 личные задачи, 3 заметки и 5 писем. Все адреса демонстрации используют зарезервированный домен `example.test`.

В деморежиме:

- никакие интеграционные запросы во внешние сервисы не выполняются;
- отправка письма переносит его в локальные «Отправленные» с отметкой о тестовой отправке;
- изменения сохраняются и переживают перезапуск;
- переключение режима не удаляет данные: рабочий и демонстрационный наборы отделены флагом на записях;
- отключённые модули скрываются из меню и ограничиваются серверными сценариями; записи остаются в хранилище.

## Подключение сервисов

Адреса ваших серверов, необходимые доступы и текущая готовность адаптеров: [docs/integrations-setup.md](docs/integrations-setup.md).

В почте и Битриксе доступен общий предпросмотр: изображения и PDF с масштабированием, DOCX со страницами, таблицами, изображениями и оформлением, XLSX с листами, объединёнными ячейками, стилями и форматами чисел, текст/CSV и извлечённый текст PPTX. Файлы обрабатываются локально. Скачивание оригинала доступно отдельно; сложное офисное оформление может отличаться. Это просмотр, без редактирования документов. [Возможности и ограничения](docs/office-preview.md).

На Windows Jira, Битрикс и Confluence подключаются через раздел «Интеграции»; почта — через `scripts/configure-mail.ps1`. Параметры окружения задаются в `.env`, который не коммитится. После изменения окружения перезапустите сервер или Docker-контейнер. Отключите деморежим в настройках. IMAP проверяется автоматически; Jira и состав команды Битрикса — каждую минуту, также доступна ручная синхронизация.

### Jira Cloud / Server / Data Center

```dotenv
JIRA_URL=https://company.atlassian.net
JIRA_EMAIL=you@company.ru
JIRA_API_TOKEN=your-token
JIRA_JQL=project = TEAM ORDER BY updated DESC
```

Тип подключения выбирается в форме: Server / Data Center с PAT или Cloud с email и API token. Задачи загружаются страницами через соответствующий REST API. По умолчанию выборка ограничена действующими участниками команды Битрикса, после сопоставления аккаунтов; альтернативно можно задать собственный JQL. Импортируются название, описание, статус, приоритет, проект, исполнитель, оценка и сроки. План по дням сохраняется отдельно. Лимит одной синхронизации — 10 000 задач: при превышении нужно сузить JQL. В интерфейс весь архив не передаётся.

### Битрикс24

Область интеграции: **сообщения и чаты, новости, сотрудники и структура компании, файлы, календарь**. Входящий вебхук вводится в форме подключения. Состав команды определяется по руководящим отделам пользователя вебхука и их подотделам. Импорт задач Битрикс24 отключён; задачи отдела поступают из Jira.

### Почта: IMAP и восстановление после выключения ПК

Основной адаптер теперь IMAP с проверяемым TLS. Настройка, Docker secrets, Windows DPAPI и алгоритм — [docs/mail-sync.md](docs/mail-sync.md).

```dotenv
MAIL_PROVIDER=imap
IMAP_HOST=<подтверждённый сервер провайдера>
IMAP_PORT=993
IMAP_USER=you@company.ru
IMAP_PASSWORD_FILE=<путь к файлу с паролем на сервере>
MAIL_SYNC_INTERVAL=20s
```

На Windows используйте `scripts/configure-mail.ps1`: пароль вводится скрыто и сохраняется через DPAPI. После перезапуска отключите деморежим. IMAP читает все доступные папки, оригиналы EML и вложения. Доступны HTML, встроенные изображения, предпросмотр файлов, черновики, ответы и пересылка. Отправка работает через настроенный SMTP по явному нажатию кнопки пользователем.

Worker работает без открытого браузера. Сразу после старта он продолжает с курсоров UID/UIDVALIDITY, сохранённых вместе с письмами. Сбой сети не откатывает уже записанные порции; повторные попытки используют backoff. Смена UIDVALIDITY вызывает повторное чтение с проверкой содержимого на дубли. Статус и ошибки видны на экране почты.

Письма свыше 25 МиБ сохраняются только заголовками с явным предупреждением; остальные оригиналы сохраняются целиком. Серверные удаления и изменения флагов не зеркалируются. Список переписок и история используют серверную пагинацию и индексы SQLite.

Альтернативный адаптер Microsoft Graph сохранён: `MAIL_PROVIDER=graph`, `MS_GRAPH_ACCESS_TOKEN`, `ALLOW_LIVE_MAIL_SEND=false`. Это прежний ограниченный импорт входящих (до 500 сообщений, без delta tokens) и отправка при явном включении флага. Токен обновляется вручную. Гарантии курсоров IMAP на Graph не распространяются. Неопределённая отправка никогда не повторяется автоматически.

## Планирование команды и пагинация

Версия 0.2.4: нажмите на день сотрудника, выберите его задачи «К выполнению» / «В работе» и сохраните план. Часы на день необязательны, одна задача может занимать несколько дней. Бэклог получает страницы с сервера: 20 задач в колонке доски, 25 в таблице. Описания открываются отдельно, счётчики учитывают всю выборку. Подробности и ограничения переноса проекта: [docs/team-day-plan.md](docs/team-day-plan.md).

## Правила расчётов

- Загрузка: сумма часов, вручную заданных в командном плане на выбранную неделю / доступные часы участника. Задачи без часов видны в плане, но не увеличивают загрузку. Включены все 7 дней недели.
- Личные задачи не попадают в командную загрузку и отчёты.
- Отчёт включает командные задачи, выбранные в плане на дни периода, задачи со сроком в периоде и завершённые в нём. Загрузка участников берётся из часов плана; оценка объёма работ остаётся суммой полных оценок задач. Просрочка определяется на текущую дату по Москве. Снимки исторического состояния не ведутся.
- Локальные изменения импортированной задачи не записываются обратно во внешний сервис. Поля источника обновятся при следующей синхронизации; личная дата плана сохраняется.
- Успешная синхронизация заменяет задачи Jira в выбранной области. Ошибка не очищает прежний набор. Распределение по дням хранится отдельно; исчезнувшие из выборки задачи не показываются в ячейках до возвращения в источник.
- При подключении структуры Битрикс24 потребуется сопоставление сотрудников с исполнителями Jira.

## Архитектура

Подробности — [docs/architecture.md](docs/architecture.md), HTTP-контракт — [docs/api.md](docs/api.md).

Направление зависимостей: `HTTP / storage / integrations → application → ports + domain`. Домен не импортирует HTTP, файловую систему или конкретные интеграции. Конкретные реализации собираются в `backend/cmd/server/main.go`.

Фронтенд разделён на `app`, `shared`, `features`. Все сетевые запросы проходят через общий API-клиент; состояние сервера обновляется после успешной операции. Логика серверных правил остаётся на Go.

## Границы локальной версии

Это контур для одного пользователя на локальном компьютере. Авторизация, роли, multi-tenant доступ, шифрование хранилища, production observability и фоновая очередь пока отсутствуют. Не публикуйте этот экземпляр напрямую в интернет.

Хранилище — SQLite; почта хранится отдельно, задачи имеют индексы для серверных страниц, агрегатов и поиска. Основной документ задач пока обновляется целиком при записи и синхронизации; для миллионов задач потребуется нормализация записи. Старый JSON-адаптер сохранён для совместимости и тестов. Оригиналы IMAP-писем и вложения хранятся отдельными файлами по хешу.

Реальные подключения требуют доступов и проверки на ваших данных. Контрактные тесты не заменяют испытания с конкретным порталом, JQL и политиками почтового сервера.

## Обновление почтового интерфейса

Настройки показывают подключённый IMAP-адрес, отдельно от старого адреса профиля. В оформлении доступны светлая, тёмная и системная темы; выбор сохраняется в браузере. Переключатель темы также есть в верхней панели.

Список содержит переписки, а не отдельные входящие/исходящие. Новое сообщение раскрыто сверху, предыдущие открываются по нажатию. Цитаты и детали скрыты. Непрочитанное отмечено зелёным фоном и точкой. Тела и изображения свёрнутых писем не загружаются. Пагинация действует и для списка, и для длинной переписки. Поиск в папке и глобальный поиск используют индекс всей почты; страницы используют курсор, без больших OFFSET.

Для Timeweb SMTP определяется по настроенному IMAP автоматически. Форматированные письма можно отправлять, сохранять в черновики и экспортировать в EML; формат и CID-изображения сохраняются.

Подготовленную и проверенную сборку можно применить командой `& C:\git\LeadHelper\scripts\update.ps1` из вашей учётной записи Windows. Скрипт сначала проверяет доступность сохранённого IMAP-пароля, затем обновляет исполняемый файл и запускает сервис. После этого обновите страницу браузера.
